Tako 2.7.1 fixes HTTP/3 early responses and updates vulnerable QUIC dependencies. Requires Rust 1.95+.

### Fixes

- Dropping an unread or partially read HTTP/3 request body now stops the upload with `H3_NO_ERROR`, so clients accept the completed response. Cancelling a pending body read also releases the stream correctly on Tokio and compio.
- The Tokio HTTP/3 transport keeps receive streams available during cancelled reads, avoiding a panic in the released h3-quinn adapter. Request bodies remain streamed and early responses do not wait for the full upload.
- HTTP/3 dependencies require quinn-proto 0.11.19 and quinn-udp 0.5.16 or newer compatible versions, addressing RUSTSEC-2026-0523, RUSTSEC-2026-0524, and RUSTSEC-2026-0538 for downstream users as well.

### Maintenance

- Added network-level regression coverage for unread, partially read, and cancelled request bodies, including connection reuse after the response.
- Removed six redundant tests and unused release-script argument handling.

Existing public APIs and runtime defaults remain compatible with 2.7.0.
