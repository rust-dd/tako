Tako 2.5 replaces tungstenite with a WebSocket engine shared by Tokio and Compio.
All eight crates are versioned at 2.5.0 and require Rust 1.95 or newer.

### Breaking changes

- Replace `TakoWs` with `WebSocketUpgrade` and import message and error types
  from `tako::ws`. On Compio, replace the `compio-ws` feature with `compio` and `ws`.
- WebSocket `send()` buffers frames until the handler waits, the write buffer
  fills, or `flush()` is called. Call `flush()` before continuing if a frame must
  be written immediately. Sends from another task still write immediately.
- Deprecated serving functions, `Router::state`, `set_state`, and other legacy
  APIs are removed. Use the server builders and `Router::with_state`.
- Raw multipart access now returns `MultipartFields` and `MultipartError`
  instead of multer's types, so part-count and content-type limits also apply
  when reading fields directly.

The [migration guide](https://tako.rust-dd.com/docs/reference/migration-2-5)
lists every removed API and its replacement, with WebSocket examples for both
runtimes.

### Fixes

- WebSockets send a close frame when a handler returns with no socket handles
  left, panics, or reaches its lifetime limit. Subprotocol negotiation handles
  repeated header fields.
- Multipart uploads enforce configured limits and timeouts, preserve returned
  temporary files, and remove abandoned uploads.
- Cookie extraction reads repeated headers; response cookie jars emit only
  changed cookies. Accept negotiation respects `q=0`; ETag matching handles
  repeated headers and commas inside quoted tags.
- HMAC verification uses the configured timestamp header. CSRF path matching
  respects path boundaries, and IP filters reject unknown clients when
  configured to deny by default.
- SSE timers run on Compio without a Tokio runtime. Filtered signal streams
  recover after lagging behind.

All 247 selected Autobahn cases pass on Tokio and Compio. Performance and
compression groups are excluded.
